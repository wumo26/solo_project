## 用 IntelliJ IDEA 開啟

1. 選 File → Open，或歡迎畫面的 Open。
2. 選擇 `C:\Users\user\Desktop\java_project\solo_project`，開啟整個根目錄。
3. 如果詢問匯入方式，選 Gradle；使用根目錄的 `build.gradle` / `settings.gradle`。
4. Project SDK 選 Java 21。在 Settings → Build, Execution, Deployment → Build Tools → Gradle 中，Gradle JVM 也選 Java 21，Distribution 使用 Wrapper。
5. 等待 Gradle 同步完成。右側 Gradle 視窗應能看到 `solo_project_backend_end`。
6. 如果只顯示一般資料夾，可在根目錄 `build.gradle` 上按右鍵，選 Link Gradle Project（名稱依版本可能略有不同）。

前端仍由 npm 管理，不用轉成 Java 或 Gradle 模組。即使 IDE 未提供 Angular 進階功能，也可在 Terminal 執行 npm 指令。

## 啟動前後端

先確保本機 MySQL 已啟動，且存在 `quiz1150512` 資料庫與應用程式所需資料表。本次整合沒有搬移或修改 MySQL 資料庫。

根目錄的 `config/application-local.properties` 保存這台電腦原有的資料庫密碼與 JWT 金鑰，已被 `.gitignore` 排除。後端會從專案根目錄或後端子目錄的工作目錄載入此設定。

換電腦或首次 clone 時：

1. 複製 `config/application-local.properties.example`，改名為 `config/application-local.properties`。
2. 填入自己的資料庫密碼，並將範例 JWT 金鑰換成至少 32 個 UTF-8 bytes 的隨機金鑰。
3. 資料庫位置或帳號不同時，在這個本機檔案加上 `spring.datasource.url` 或 `spring.datasource.username`。
4. 若不使用本機檔案，也可在執行環境設定 `DB_PASSWORD`、`JWT_SECRET`。本機檔案存在時，其中的設定會覆寫應用程式內的對應設定。

IntelliJ 的 Terminal 1：

```powershell
cd C:\Users\user\Desktop\java_project\solo_project
.\gradlew.bat :solo_project_backend_end:bootRun
```

Terminal 2：


套件安裝後，平常只要 `npm.cmd start`；拉取更新導致 `package-lock.json` 變動時，再執行 `npm.cmd ci`。

瀏覽器開啟 <http://localhost:4200>。後端使用 8080，前端以代理轉送 `/api` 請求。如果已用舊路徑啟動服務，先在對應 Terminal 按 Ctrl+C，避免埠號衝突。

## 下次把兩個專案整合到新儲存庫

1. 在 GitHub 建立目的儲存庫。
2. 用 IntelliJ 的 Clone Repository / Get from VCS，或 PowerShell 的 `git clone`，先下載目的儲存庫。目的資料夾不存在時，clone 會建立它。
3. 在目的根目錄建立前端、後端子資料夾，分別複製實際原始碼及必要設定。
4. 複製時排除來源 `.git`、依賴套件、快取與輸出檔；不要直接把含 `.git` 的整個舊專案拖進來，否則可能變成巢狀儲存庫。
5. 檢查是否混入其他專案副本。Angular 需要 `src`、`public`（如有使用）、`package.json`、`package-lock.json`、`angular.json`、`tsconfig*.json` 與代理設定。Spring Boot 需要 `src`、`build.gradle`、`settings.gradle` 與 Gradle Wrapper。
6. 若要 IntelliJ 從同一根目錄匯入後端，可照本專案建立根目錄 `settings.gradle`，內容包含 `rootProject.name = 'solo_project'` 及 `include 'solo_project_backend_end'`，並把後端 Wrapper 複製到根目錄。
7. 在根目錄建立 `.gitignore`，並將實際密碼、金鑰放入被忽略的本機設定檔；只提交設定範例。
8. 編譯確認後再 Commit 與 Push。

目的 GitHub 儲存庫已存在時，先 clone 可保留原有歷史，也可避免首次 push 遇到 unrelated histories 或 non-fast-forward。不需要另外再執行 `git init`。

## IntelliJ 提交與上傳

本專案已設定 `origin`，指向 <https://github.com/wumo26/solo_project.git>，分支為 `main`。之後不需再初始化 Git 或新增相同 remote。

1. 打開 Commit 視窗（Windows 預設 Ctrl+K；依 keymap 可能不同）。
2. 檢查檔案清單及 diff，勾選本次要提交的變更。確認本機密碼檔沒有出現。
3. 填入說明，例如「新增問卷統計功能」，按 Commit。這一步只寫入本機歷史。
4. 選 Git → Push（Windows 預設 Ctrl+Shift+K）。
5. 確認是 `main → origin/main`，按 Push。這一步才會上傳 GitHub。
6. 若要求 GitHub 登入，由你完成 IntelliJ 或 Git Credential Manager 的登入流程。
7. 若遠端已有他人更新，先 Pull / Update Project，處理衝突，再 Push；不要直接 Force Push。

官方說明：<https://www.jetbrains.com/help/idea/commit-and-push-changes.html>

## 同樣操作的 PowerShell 指令

本專案平常更新：

```powershell
cd C:\Users\user\Desktop\java_project\solo_project
git status
git diff
git add .
git diff --cached --stat
git commit -m "Describe the change"
git push
```

檢查目前狀態與遠端：

```powershell
git branch --show-current
git remote -v
git status
git check-ignore config/application-local.properties
```

最後一個指令應輸出本機設定檔路徑，代表它已被忽略。

只有「全新本機資料夾，且 GitHub 目標儲存庫完全沒有任何提交」時，才使用以下首次初始化流程：

```powershell
git init -b main
git add .
git commit -m "Initial project import"
git remote add origin https://github.com/wumo26/solo_project.git
git push -u origin main
```

本次專案已 clone 且已有歷史，不要再跑這段初始化指令。
